# CLAUDE.md

이 파일은 이 저장소에서 작업하는 Claude Code에게 주는 지침입니다.

## 프로젝트 개요

PC_BackUp — 프로그램 폴더를 ZIP 또는 선택 폴더로 백업하고, 복원·비교·이력 조회를 제공하는
사내 도구입니다. C# / .NET 10, WinForms. 운영 장비를 제어하는 프로젝트가 아닙니다.

## 코딩 규칙

코딩 규칙과 브랜치/워크트리 규칙은 `RULES.md` 에 있습니다. **그 문서를 정확히 따르세요.**
(규칙 본문은 여기 옮겨 적지 않습니다. 두 곳에 쓰면 어긋납니다.)

## 작업 방식 — 수정 전에 반드시

**master는 직접 수정하지 않습니다.** 파일을 고치기 전에 `RULES.md` 8장 순서를 지킵니다:
이슈 생성 → 이슈 번호 브랜치 → 새 워크트리에서 작업. 워크트리 생성 명령은 `AGENTS.md` 의
"브랜치 및 워크트리 작업"에 있습니다. 일반 브랜치만 만들어 작업하는 것은 이 절차가 아닙니다.

사내 도구이므로 그 외에는 요청 범위 안에서 일반적인 개발 흐름으로 진행합니다.

## 빌드 및 검증

빌드와 실행 검증은 **사용자가 직접** 합니다. 코드만 수정하고, 필요한 명령은 안내만 하세요.
자동화된 테스트는 없습니다.

## 절대 하지 말 것

- `master` 작업 폴더에서 파일 수정 금지.
- `git add .` 금지. 의도한 파일만 스테이징하세요.
- `.bak`, `_backup`, `복사본` 이 붙은 파일은 수정하지 마세요.
- 커밋·푸시·PR은 사용자가 요청할 때만 합니다.
- 이 프로젝트의 WinForms 화면은 VS 디자이너로 열리지 않습니다. `.Designer.cs` 는 코드로 직접 수정하세요.

## 문서 작성 규칙

분석·리뷰 결과는 `docs/review/YYYY-MM-DD_#이슈번호_영문슬러그_KO.md` 로 저장한다.
설계·흐름·매뉴얼 문서는 각각 `docs/design/`, `docs/flow/`, `docs/manual/` 에 날짜 없이 저장한다.
문서에는 "확인하지 못한 것" 섹션을 반드시 포함한다.
상세 기준은 `docs/standards/문서_구조와_명명규칙.md` 를 따른다.

## 참조 문서

- `RULES.md` — 코딩·브랜치 규칙 (최종 권위)
- `AGENTS.md` — 워크트리 명령, Codex 협업 규칙
- `docs/UI_UX_DESIGN_SYSTEM_RULES.md` — 화면(UI)을 만질 때

## 출력 방식

- 간결하게, 핵심만 답하세요. 근거가 부족하면 추측하지 말고 "확인이 필요하다"고 말하세요.
- 작업을 마치면 확인한 파일 / 변경한 파일 / 남은 불확실성 / 다음 검증 단계를 보고하세요.
