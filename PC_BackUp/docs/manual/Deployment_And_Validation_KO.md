# 배포·진단·사용자 검증

- 갱신: 2026-10-19 / Codex

## 데이터 위치

- 기존 프로그램 루트의 Config/PCBackupSettings.xml이 있으면 위치를 유지합니다.
- 프로그램 루트에 portable.mode 파일을 두면 해당 루트의 Config와 Logs를 사용합니다.
- 신규 일반 배포는 사용자 LocalAppData/PC_BackUp을 사용합니다. _bin 밖 실행도 지원합니다.
- portable/기존 위치는 쓰기 권한이 필요합니다. 쓰기 실패 시 시작·저장 오류를 확인하고 위치 또는 권한을 수정합니다.
- 실행 중인 프로그램·설정과 복구 저널 폴더는 신뢰된 계정만 수정하도록 유지합니다.

## 진단

- JSONL에 UTC 시각·작업 ID·결과 상태·전체 예외·실패 항목을 기록합니다. 최근 로그 UI는 구버전 로그도 읽습니다.
- 5MB 기준 회전 로그와 원본 로그를 이력 화면의 진단 내보내기로 ZIP 저장할 수 있습니다.
- 로그 쓰기 실패는 대시보드 경고에서 확인합니다. 진단에는 경로·예외가 포함되므로 공유 전 내용을 확인합니다.

## 사용자 검증 순서

1. #13부터 #27까지 각 PR 기준 브랜치의 변경을 순서대로 검토합니다. 전체 조합은 fix/issue-27에 있습니다.
2. 솔루션을 Visual Studio로 빌드하고 시험 폴더에서 실행합니다. 빌드·실행은 사용자가 수행합니다.
3. 각 이슈의 docs/review 문서 체크리스트를 수행합니다. 접근 거부·잠금·취소·강제 종료 시험은 복제 데이터만 사용합니다.
4. ZIP/선택 폴더 백업 생성 → manifest 검증 → XML 비교/파일 복원 → 전체 복원/롤백 순서로 확인합니다.
5. GUI 최소 크기·빈 목록·대량 목록·125/150% DPI, _bin 외부 실행·portable·일반 설치 데이터 경로를 확인합니다.
6. 진단 내보내기와 로그 폴더 쓰기 실패 경고를 확인합니다.

## 미해결 / 논의 필요

빌드·실행·성능·강제 종료 복구 시험은 아직 수행하지 않았습니다. 자동화 테스트 프레임워크 도입과 저장소 CI는 별도 합의가 필요하며 이 변경에서 새 패키지는 추가하지 않았습니다.
