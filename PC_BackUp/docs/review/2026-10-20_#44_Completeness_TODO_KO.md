## 1. XML 선택 단위와 실제 적용 범위

### 원인과 영향

최초 코드에서는 값별로 체크하지만 서비스는 파일별로 묶어 백업 XML 전체를 교체했다.
하나의 파일에서 A만 선택해도 B 등 미선택 값이 함께 바뀌어 사용자의 기대와 실제 결과가 달랐다.
선택 행 수를 파일 수로 표시하는 문제도 있었다.

### 현재 구현 확인

- [x] 버튼을 “선택 파일 전체 복원”으로 표시하고, 확인창에서 미선택 값을 포함한 파일 전체 교체임을 안내한다.
- [x] 같은 상대 경로의 행 선택을 두 그리드에서 동기화한다.
- [x] 확인창은 고유 상대 경로의 개수와 목록을 표시하며 서비스도 파일별 중복을 제거한다.
- [x] 현재에만 있는 파일은 복원 선택에서 제외한다.
- [x] 비교 후 설정·파일 변경을 검사하고 공통 복원 안전 절차 및 RestoreTransaction을 사용한다.

이는 “선택한 값만 패치”를 구현한 것이 아니라 “선택한 파일 전체 복원”으로 계약을 통일한 수정이다.
값 단위 적용을 원한다면 namespace·노드 존재 차이·충돌 처리까지 포함하는 별도 설계가 필요하다.

## 2. 접근 불가 경로 누락과 백업 성공 판정

열거 단계의 누락과 실제 파일 복사 중 발생하는 실패는 구분해야 한다.

- [x] 선별 백업은 선택된 루트만 탐색한다.
- [x] 미완성 이름으로 생성하고 manifest 작성·검증을 거쳐 완료 이름으로 게시한다.

## 5. 복원 실패·취소·강제 종료 후 복구

### 원인과 영향

최초 복원은 파일을 순서대로 직접 덮어써 중간 오류·취소 시 일부만 바뀐 상태가 남았다.
안전 백업 옵션은 복구 원본을 만드는 기능이며 자동 롤백을 대신하지 않았다.
ZIP 해제에도 취소 토큰을 전달하지 않아 큰 압축 파일에서 취소 반응이 늦어질 수 있었다.

### 현재 구현 확인

- [x] RestoreTransaction이 복원본과 기존 파일을 먼저 확보한 후 파일별 쓰기 전에 저널을 저장한다.
- [x] 오류·취소 시 역순 롤백하고 새로 생성한 파일을 제거하며, 롤백은 CancellationToken.None으로 보호한다.
- [x] 롤백 실패는 AggregateException으로 전달하고 복구 기록을 보존한다.
- [x] MainForm 초기화에서 미완료 저널을 검사하여 대상 잠금 아래 복구한다.
- [x] ZIP 해제와 FileTransfer 버퍼 복사에 취소 토큰이 전달된다.
- [x] ZIP 항목 수·총량·경로·필요 공간 등의 제한이 추가되었다.

### 잔여 분석

저널·사본은 현재 Windows 사용자의 LocalAppData에 저장된다.
다른 계정으로 실행하면 같은 복구 기록을 자동 발견한다는 보장이 없다.
여러 파일을 한 번에 교체하는 파일시스템 전체 원자성이나 전원 상실·저장장치 고장까지 보장하지 않는다.
4번의 잠금이 복구를 막는 상황도 함께 검증해야 한다.

### 완료 조건

지원하는 오류·취소 시나리오에서는 복원 전 상태를 복구하고 그 결과를 보고해야 한다.
자동 복구가 불가능하면 실패를 명확히 알리고 저널·사본을 보존해야 한다.
원복 실패를 성공이나 단순 취소로 표시해서는 안 된다.

2. 4번의 잠금과 완료 게시를 먼저 검증한다. 이후 검증 도중 작업 경합을 방지하는 선행 조건이다.
3. 2번의 백업 완전성과 3번의 비교 정확성을 확인해 복구 원본·판단의 신뢰성을 확보한다.
4. 5번의 복원 저널·롤백·재시작을 검증한 후 1번 XML 파일 복원까지 통합 검증한다.

시험은 운영 원본과 분리된 임시 데이터로 수행한다.

## 확인하지 못한 것

- 빌드·프로그램 실행·자동화 테스트·운영 데이터 복원은 수행하지 않았다. 저장소 지침에 따라 사용자 수행 예정이다.
- 실제 UI 선택 동기화, 접근 거부·디스크 부족·강제 종료 및 롤백 실패를 재현하지 않았다.
- 닫힌 관련 이슈의 모든 완료 조건이 실제로 검증되었는지는 확인하지 않았다. 기존 구현 보고서에도 실행 검증은 사용자 수행 예정으로 남아 있다.
- 잠금의 부모/자식 범위, 다중 세션·계정·경로 별칭, 네트워크 저장소의 동작은 확인하지 않았다.
- 취소 반응 시간, 대용량 성능, 복구용 LocalAppData 용량은 측정하지 않았다.
- 이 문서는 5개 항목의 후속 작업 분석이며 최신 전체 프로젝트의 점수를 다시 산정한 보고서는 아니다.
- 기준 커밋 이후 변경은 포함하지 않는다. 후속 작업 시작 시 해당 이슈와 소스를 다시 확인한다.
