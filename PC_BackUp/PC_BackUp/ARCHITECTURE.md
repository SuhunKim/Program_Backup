# PC Backup Manager 기획 및 아키텍처

## 1. 목표

지정된 Windows 프로그램 폴더를 수동 백업하고, 날짜/시간별 백업을 조회·복원하며, XML 설정의 변경점만 선택 적용할 수 있는 WinForms 도구를 만든다.

- 개발 환경: C# 11, WinForms
- 대상 프레임워크: `.NET 7.0 Windows` (`net7.0-windows`)

초기 버전의 우선순위는 다음과 같다.

1. 잘못된 경로로 복원하지 않는 안전성
2. 백업 파일만 보고도 생성 시간을 알 수 있는 단순한 규칙
3. UI와 파일 처리 로직을 분리해 향후 예약 백업, 보존 정책, 로그 기능을 쉽게 추가할 수 있는 구조

## 2. 계층 구조

같은 작성자의 다른 프로그램(PC_Setting)과 폴더 컨벤션을 맞춰 유지보수 감각을 통일했다. (도메인이 다른 `ComputerManagement`/`LocalAccount` 같은 폴더는 PC_Setting 고유 기능이라 가져오지 않고, `_utility` 공용 부품 · `ActiveMenuManager` · `ControlPresenter` 패턴만 이식했다.)

`_util/FileNaming.cs`(폴더명 유효성 검사 및 백업 파일명 접미사 정리)와 `_util/ProgramPaths.cs`(조상 폴더 탐색 — PC_BackUp 자신의 프로그램 루트 및 대상 프로그램의 원본 루트 계산에 공용으로 쓰인다)도 공용 유틸리티로 추가되었다.

- 각 메뉴 화면은 `UserControlBase`를 상속해 `IMenuPage.OnMenuSelected()`만 구현한다.
- `MainForm`은 `MainMenuControl`(사이드바)과 `ActiveMenuManager`(메뉴 전환 조율)를 조립하는 얇은 호스트로, 메뉴 전환 로직 자체는 갖지 않는다.
- `Services`는 UI 컨트롤을 참조하지 않아 추후 테스트 프로젝트에서 단독 검증할 수 있다.
- 서비스 인스턴스는 `MainForm.Initialize()`에서 만들고 생성자로 전달한다. 별도 DI 패키지는 기초 단계에서는 사용하지 않는다.

## 3. 핵심 데이터 구조

```csharp
Dictionary<DateTime, List<BackupRecord>> recordsByDate;
```

- 키는 시간 부분을 제거한 `DateTime.Date`이다.
- 값은 해당 날짜의 백업이며 최신 시간이 먼저 오도록 정렬한다.
- 파일 시스템을 원본 데이터로 삼고 화면 진입 또는 백업 완료 시 카탈로그를 다시 만든다.
- 별도 DB가 없어 백업 폴더를 다른 PC로 옮겨도 목록을 복원할 수 있다.

`BackupRecord`는 생성 시각, 백업 형태, 전체 경로, 파일명, 크기를 가진다.

## 4. 파일 및 설정 규칙

| 구분 | 규칙 |
|---|---|
| 전체 백업 | `yyyy-MM-dd HH:mm[-접미사][-01].zip` |
| 선별 백업 | `yyyy-MM-dd HH:mm[-접미사][-01]_files.zip` (항상 zip 압축 — 대시 앞뒤 공백 없는 이전 형식과 구버전 `<접두사>_yyyyMMddHHmmss` 형식도 복원/비교/이력 목록에서 계속 지원) |
| 파일명 접미사 | 기본은 없음(시간만으로 충분). 백업 실행 전 뜨는 다이얼로그에서 "파일명에 프로젝트명 추가" 체크박스를 켜면 원할 때만 덧붙일 수 있다. Windows 파일명에 쓸 수 없는 문자는 거부하지 않고 입력하는 즉시 자동으로 제거된다. |
| 같은 분 충돌 처리 | 시간을 바꾸지 않고 순번만 붙인다 — 같은 분에 처음 만든 백업은 순번 없이, 두 번째부터 ` - 01`, ` - 02`… 순으로 구분한다(최대 99개). |
| 설정 파일 | PC_BackUp 실행 폴더 `_bin`의 형제 폴더 `Config\PCBackupSettings.xml` |
| 로그 파일 | PC_BackUp 실행 폴더 `_bin`의 형제 폴더 `Config\Logs\pcbackup.log` |
| 원본 루트 | 실행 파일이 선별 폴더(예: `_bin`) 안에 중첩되어 있으면 그 조상 폴더의 부모, 못 찾으면(과거처럼 exe가 루트에 바로 있는 구조) exe의 직계 부모 폴더 |
| ZIP 범위 | 원본 루트 전체. 백업 폴더가 원본 내부이면 해당 폴더 제외 |
| 선별 범위 | 환경설정에서 개수 제한 없이 추가한 폴더 목록 전체(기본값 `_bin`, `Config`이며 최소 1개는 항상 유지) |

설정 파일은 임시 파일 작성 후 교체해 저장 도중 손상될 가능성을 낮춘다.

## 5. 화면 구조

네 화면 모두 `ColorRGB.CreatePageHeader(title, description)`로 제목(굵고 큼)과 설명(작고 옅음)을 서로 다른 Label로 분리해 표시한다. 저장/시작처럼 매번 필요한 주 action 버튼은 스크롤되는 본문과 별도로 화면 하단에 고정 배치해, 내용이 길어져도 늘 보이게 한다.

```text
┌──────────────────┬────────────────────────────────────────────────────┐
│ PC BACKUP        │ 화면 제목 / 설명                                  │
│ MANAGER          ├────────────────────────────────────────────────────┤
│                  │                                                    │
│ 01 백업          │ 선택 메뉴의 작업 영역                             │
│ 02 복원          │                                                    │
│ 03 이력 관리     │                                                    │
│ 04 환경 설정     │                                                    │
│                  │                                                    │
│ v0.1 Foundation  │ 상태 / 실행 버튼                                  │
└──────────────────┴────────────────────────────────────────────────────┘
```

### 01 백업

```text
[프로젝트 / 원본 위치 / 백업 위치 요약]
[● 전체 ZIP]  [○ 지정 폴더 선별 백업]
[진행률 / 상태]                          [취소]  [백업 시작]
```

- 설정이 유효하지 않거나 다른 작업이 진행 중이면 백업 버튼을 비활성화한다(화면을 벗어났다 돌아와도 진행 중에는 계속 비활성 유지).
- 백업 시작 전 파일명 확인 다이얼로그가 뜬다(기본은 `yyyyMMdd - HHmm`만 사용, "파일명에 프로젝트명 추가" 체크박스를 켜면 원할 때만 뒤에 이름을 덧붙일 수 있음. 미리보기가 즉시 갱신됨).
- 파일 단위 진행률을 표시하며, 진행 중에는 취소 버튼으로 중단할 수 있다.
- 실패/성공 결과와 예외는 `Config\Logs\pcbackup.log`에도 기록된다.

### 02 복원

```text
[백업 날짜 달력] | [시간 | 백업 형태 | 파일명 | 크기]
                 |
                 | [선택 백업: 파일명 · 시각 · 형태 · 크기]
                 | [복원 위치: <원본 루트>]
                 | [✔ 복원 전 현재 상태를 자동 ZIP 백업]
                 |                      [취소]  [선택 백업 복원]
```

- 백업 또는 작업 로그가 있는 날짜는 이력 전용 달력에서 볼드와 파란 점으로 강조하고, 이력이 없는 날짜는 연한 회색으로 표시한다.
- 목록에서 백업을 고르면 그리드 아래 상세 패널에 선택한 백업의 파일명·시각·형태·크기와 실제 복원될 위치(원본 루트)를 바로 보여준다 — 복원 버튼을 누르기 전에 무엇을 어디에 덮어쓰는지 한눈에 확인 가능.
- "복원 전 현재 상태를 자동 ZIP 백업" 체크박스가 상세 패널에 있다. 켜면 덮어쓰기 직전 전체 ZIP 안전 백업을 먼저 만들고, 상태는 토글 즉시 `PCBackupSettings.xml`에 저장되어 재실행 후에도 유지된다(기본값은 꺼짐). 환경설정 화면에는 이 옵션이 없다 — 실제로 쓰는 복원 화면에 바로 두었다.
- 복원 전 대상 경로와 덮어쓰기를 재확인한다.
- 대상 EXE와 같은 이름의 프로세스가 실행 중이면 종료 여부를 물은 뒤 정상 종료, 5초 후 강제 종료 순으로 처리한다.
- 복원은 백업 파일을 원본 위에 덮어쓰며, 백업에 없는 현재 파일은 삭제하지 않는다. 진행 중에는 취소 버튼으로 중단할 수 있다.

### 03 이력 관리

```text
[비교할 백업 선택 ▾]        [즉시 백업 ▾] [작업 로그] [XML 비교]
[적용 | 항목명(XML 파일 + 경로) | 현재 값 | 백업 값]
[  (비교 전/결과 없음이면 안내 문구로 대체)  ]
[진행률]
[전체 선택/해제] [차이점 요약]              [취소]  [선택 설정 적용]
```

- 툴바는 우선순위대로 배치한다: 이 화면의 주 목적인 "XML 비교"가 가장 오른쪽·강조색(Primary)으로 가장 눈에 띄고 바로 왼쪽에 "작업 로그"·"즉시 백업"이 옅은 색(Secondary) 보조 동작으로 붙는다. 비교 대상을 고르는 콤보는 왼쪽에서 남는 공간을 채운다.
- 비교를 실행하기 전이나 결과가 0건일 때, 그리고 작업 로그가 비어있을 때는 빈 그리드 대신 안내 문구를 가운데에 보여준다("비교할 백업을 선택한 뒤 XML 비교를 실행하세요." / "기록된 작업 로그가 없습니다." 등).
- XML의 리프 요소 값과 특성(attribute)을 비교한다.
- 파일 상대 경로와 namespace에 독립적인 XPath를 항목 키로 사용한다.
- 현재 문서에도 존재하는 항목을 선택 적용한다. 백업에만 존재하는 새 XML 노드 생성은 후속 범위이다.
- 진행률 표시: 즉시 백업은 `BackupService`가 제공하는 파일 단위 진행률을 그대로 표시하고, XML 비교/적용은 서비스가 세부 진행률을 제공하지 않아 마퀴(불확정) 진행률로 작업 중임을 표시한다. 모든 작업은 취소 버튼으로 중단할 수 있다.
- "작업 로그" 토글 버튼을 누르면 그리드가 백업/복원/비교/적용 작업 로그 목록(시간·레벨·메시지)으로 전환된다. 다시 누르면 비교 결과 화면으로 돌아간다.
- 즉시 백업도 시작 전 같은 파일명 확인 다이얼로그를 거친다.

### 04 환경 설정

```text
┌─ (스크롤되는 본문) ──────────────────────────────────┐
│ [타겟 프로젝트 이름                                  ] │
│ [실행 파일 원본 경로                          ][찾기] │
│ [백업 저장 위치                               ][찾기] │
│ 선별 백업 대상 폴더                       [＋ 폴더 추가]│
│ [선별 백업 대상 폴더 목록 (각 행: 이름 | 찾기 | －)]   │
└──────────────────────────────────────────────────────┘
                                                   [저장]   ← 화면 하단 고정
```

- 실행 파일/백업 폴더/선별 폴더 찾아보기 다이얼로그의 기본 시작 위치는 `D:\_program`(없으면 `D:\`)이다.
- "실행 파일 찾기"로 exe를 직접 선택하면, 그 경로 바로 바깥(형제 폴더)에 현재 목록에 있는 이름(기본 `_bin`/`Config` 포함)과 같은 폴더가 실제로 있는 경우에만 자동으로 목록에 추가한다(없는 이름은 건너뜀).
- 선별 백업 대상 폴더는 개수 제한 없는 목록이다. "＋ 폴더 추가" 버튼은 각 행의 [찾기][－] 버튼 폭에 맞춰 그 열 바로 위, 목록 제목 줄의 가장 오른쪽에 있다. 클릭하면 폴더 선택창이 반복해서 뜨는 방식으로 여러 개를 연달아 추가할 수 있고(매번 "더 추가할까요?"로 확인), 탐색기에서 폴더 여러 개를 선택해 목록 위로 드래그&드롭해도 한 번에 추가된다(이미 있는 이름은 건너뜀). 각 행의 "－"로 제거하며 최소 1개는 항상 유지된다.
- "설정 저장" 버튼은 스크롤되는 본문과 분리된 화면 최하단 고정 바에 있어, 항목이 많아 스크롤해도 항상 보인다.
- "복원 전 자동 안전 백업" 옵션은 여기 없다 — 02 복원 화면의 상세 패널로 옮겼다(§02 참고).

## 6. 주요 처리 흐름

### 백업

1. 파일명 확인(다이얼로그, 이름 덧붙이기는 선택) — 취소 시 백업을 시작하지 않음
2. 설정값과 경로 검증
3. 파일명 충돌 확인(최대 약 하루 분량 재시도)
4. 원본 파일 열거 및 백업 경로 자기 포함 방지
5. ZIP 생성(전체/선별 모두 압축) — 취소 토큰으로 중단 가능
6. 실패 시 생성 중이던 결과 제거
7. 카탈로그 새로고침, 로그 기록, UI 결과 표시

### 복원

1. 백업 선택 및 사용자 덮어쓰기 확인
2. 실행 중인 대상 프로세스 확인/종료
3. "복원 전 자동 안전 백업"이 켜져 있으면 현재 상태를 전체 ZIP으로 먼저 백업(실패 시 계속할지 확인)
4. ZIP이면 고유 임시 폴더에 해제(구버전 폴더 백업이면 그대로 사용)
5. 대상 루트를 벗어나는 상대 경로 차단
6. 원본 폴더에 파일 단위 덮어쓰기 — 취소 토큰으로 중단 가능
7. 임시 폴더 정리, 로그 기록, 결과 표시

### 부분 설정 적용

1. 현재와 백업의 XML을 상대 경로별 로드
2. 요소/특성 값을 XPath 키로 평탄화
3. 다른 값만 그리드에 표시
4. 사용자가 체크한 노드를 현재 XML에서 찾음
5. 임시 파일에 저장 후 원본 XML 교체

## 7. 후속 개발 권장 순서

이미 구현됨:
- ~~백업 전 파일 잠금 검사와 복원 전 자동 안전 백업 추가~~ → 자동 안전 백업은 복원 화면 상세 패널의 체크박스로 구현(기본 꺼짐, 토글 즉시 저장). 파일 잠금 사전 검사는 아직 없음(실행 중 프로세스 확인/종료로 대신함).
- ~~Serilog 등 파일 로그와 작업 결과 이력 추가~~ → `LogManager`가 `Config\Logs\pcbackup.log`에 기록하고, 이력 관리 화면의 "작업 로그" 토글로 조회 가능.
- ~~대용량 파일 취소 버튼~~ → 백업/복원/비교/적용 모두 취소 버튼 추가.

남은 항목:
1. 실제 대상 프로그램에서 `_bin`, `Config` 폴더의 위치와 권한 검증, 백업 전 파일 잠금 검사
2. 백업 보존 개수/기간 및 오래된 백업 정리 기능 추가
3. 예약 백업과 Windows 시작 시 실행 옵션 추가
4. 대용량 백업 예상 용량, 남은 시간 표시 추가
5. 서비스 계층 단위 테스트 및 임시 디렉터리 기반 통합 테스트 추가

## 8. 현재 결정이 필요한 항목

- ~~선별 백업 기본 폴더명은 `_bin`, `Config`이며 환경 설정에서 각각 변경할 수 있다.~~ → 개수 제한 없는 목록으로 확장(＋/－, 최소 1개).
- ~~여러 프로젝트가 같은 백업 폴더를 공유할 경우 파일 접두사를 `program` 대신 프로젝트 이름으로 바꿀지 결정해야 한다.~~ → 파일명은 기본적으로 시간(`yyyyMMdd - HHmm`)만 사용하고, 여러 프로젝트가 폴더를 공유하는 등 구분이 필요할 때만 다이얼로그의 체크박스로 뒤에 이름을 선택적으로 덧붙이도록 해소(입력값의 금지 문자는 자동 제거).
- ~~복원 전에 현재 상태를 자동 ZIP으로 보관할지 결정해야 한다.~~ → 복원 화면 상세 패널의 체크박스로 구현(토글 즉시 저장), 기본값은 꺼짐. 실제로 쓰는 화면에 바로 두어 환경설정 화면에는 이 항목이 없다.
- 복원 때문에 종료한 대상 프로그램을 완료 후 자동 재실행할지는 아직 미결정.
